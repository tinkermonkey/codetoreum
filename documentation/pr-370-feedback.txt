  2. [FIXED] RepositoryStatus name collision between two port files
  [type-design-analyzer] — ports/output/version_control_service.py + ports/output/repository.py

  Two classes named RepositoryStatus exist in the port layer: a 3-field version (no validation) in
  version_control_service.py and a 7-field, fully-validated version in repository.py that
  ports/output/__init__.py exports. InMemoryVersionControlService constructs the 3-field version.
  Any caller receiving a status() result and accessing .current_branch or .ahead_count gets
  AttributeError at runtime. Fix: rename the VCS version to VCSStatus or extend the repository.py
  version to eliminate duplication.

  3. [FIXED] LockStuckEvent silently fails to persist via EventBus
  [code-reviewer] — board_event_handler.py:395–413

  EventBus.publish() is typed for DomainEvent, but LockStuckEvent is a CodetoreumEvent that lacks
  aggregate_id, aggregate_type, and occurred_at. Redis persistence will raise AttributeError at
  runtime, caught by the defensive try/except — the event is never written to the event store. The
  observability signal that justifies the event's existence is silently lost. Fix: either make
  LockStuckEvent extend DomainEvent with proper aggregate fields, or emit it through IEventEmitter
  instead of EventBus.
